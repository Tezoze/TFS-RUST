## Gap 7c — Gap 7a is **not** complete (new)

> **Landed 2026-08-13.** The failures below were the 7c starting state. After 7c, all five `data/scripts/lib` files load (`scripts_lib_files_load_with_zero_failures`); `all_class_globals_are_tables` enumerates every `register_class` global.

The claim "`register_class` is the only way a class global is created" and "the bug class cannot recur: there is no longer an API that replaces a class table with a function" are **false**. The *userdata* classes were converted; the *revscript constructor* globals were not:

| Global | Registered as | Site |
|---|---|---|
| `Action` | bare function | `runtime.rs:1452` |
| `TalkAction` | bare function | `runtime.rs:1395` |
| `MoveEvent` | bare function | `runtime.rs:1544` |
| `Channel` | bare function | `runtime.rs:1304` |
| `Condition` | bare function | `runtime.rs:1321` |
| `Variant` | bare function | `runtime.rs:1237` |
| `MonsterType` | bare function | `userdata/monster_type.rs:108` |
| `CreatureEvent`, `GlobalEvent` | **not registered** (`nil`) | — |

Consequence — **3 of 5 `data/scripts/lib/**` files fail to load today** (silently, warn-and-continue):

```
### stage scripts/lib (5 files)
  FAIL create_functions.lua:1     attempt to call global 'createFunctions' (a nil value)
  OK   defaults_move_event.lua
  OK   event_callbacks.lua
  FAIL helper_constructors.lua:5  attempt to index local 'MT' (a nil value)   -- getmetatable(Action) == nil
  FAIL register_monster_type.lua:14 attempt to index global 'MonsterType' (a function value)
### stage scripts/*.lua (2 files) — OK functions.lua, OK scarab_tiles.lua
```

- `register_monster_type.lua:12` does `MonsterType.register = function(self, mask)` — the identical Gap 7a failure mode, one `register_class` call from fixed.
- `helper_constructors.lua:1-5` takes `getmetatable(class).__call` for `{Action, CreatureEvent, Spell, TalkAction, MoveEvent, GlobalEvent, Weapon}` to add the table-definition constructor form. Needs all seven to be class tables *with* `__call`. `Spell`/`Weapon` already qualify (7a); the other five do not.
- `create_functions.lua` calls `createFunctions(MonsterType)` / `createFunctions(Spell)`, defined only at `data/lib/compat/compat.lua:1408` — which [resolved decision #3](decisions.md#resolved-decisions) deliberately does not load. This one is a **policy conflict, not a bug**: either load compat, port `createFunctions` to Rust/`data/lib/core`, or exclude the file from the fatal set.

**This invalidates the Gap 7 scope note** claiming "nothing in the data pack extends `Spell`, `Weapon`, or `Condition` — converting those is speculative work with no consumer." `helper_constructors.lua` is a real consumer of `getmetatable(Spell)` / `getmetatable(Weapon)`; converting them was correct, and `Condition` still needs it.

## Gap 5a was blocked by 7c — **landed 2026-08-13**

The 7c starting state would have aborted boot on three `data/scripts/lib` files. After 7c those load clean, and Gap 5a flipped the lib stage to fatal (`LuaError::LibStageFailures`, `run_server.rs` bails). `core.lua`/`lib.lua` are skipped in the scan, so the double-load and CWD-relative `dofile` hole are gone.

Historical notes from the 7c-era probe (kept so the 7c starting state stays documented):

- `core.lua` **loaded successfully** and `dofile`d 15 of the other 16 core files, so the recursive scan + `core.lua` **double-loaded** every core file except `actionids.lua`.
- `core.lua`'s `dofile` is CWD-relative, so outside the repo root it failed and the *other 16 files still loaded* via the scan. That asymmetry is why the failure was invisible under warn-and-continue.
